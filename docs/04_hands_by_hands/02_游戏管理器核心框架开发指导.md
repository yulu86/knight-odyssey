## 需求概述

### 用户故事
作为一名**开发者**，我想要**有一个统一的游戏管理框架**，以便**协调各个系统之间的交互和管理游戏状态**

### 验收标准（AC）
1. ✅ 游戏启动时，GameManager应初始化所有子系统
2. ✅ 场景切换时，GameManager应协调资源加载和释放
3. ✅ 触发游戏事件时，EventBus应正确分发事件到订阅者
4. ✅ 需要配置参数时，ConfigManager应从文件加载配置
5. ✅ 保存进度时，GameManager应调用相应的管理器保存数据
6. ✅ 所有管理器使用AutoLoad机制，全局可访问
7. ✅ 系统间通过事件解耦，避免直接依赖

### 技术实现
- AutoLoad单例模式
- EventBus事件系统
- ConfigFile配置管理

## TDD开发步骤

### 🎯 TDD微循环（红-绿-重构）

每个功能开发都严格遵循以下循环：

```
┌─────────────────────────────────────────────────────────┐
│  🔴 RED - 编写测试（让测试失败）                          │
│  ├── 理解需求                                           │
│  ├── 编写测试用例                                       │
│  └── 运行测试，确认失败                                 │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  🟢 GREEN - 实现最小代码（让测试通过）                   │
│  ├── 编写最少代码                                       │
│  ├── 不追求完美，只求通过                               │
│  └── 运行测试，确认通过                                 │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│  ♻️ REFACTOR - 重构优化（保持测试通过）                  │
│  ├── 优化代码结构                                       │
│  ├── 消除重复，提高可读性                               │
│  └── 确保所有测试持续通过                               │
└─────────────────────────────────────────────────────────┘
```

## 🔧 常见问题

### Q1: ConfigManager是RefCounted，不能作为AutoLoad怎么办？
**A**: 创建一个包装器Node，在包装器中持有ConfigManager实例。

### Q2: 测试时GameManager不是AutoLoad怎么办？
**A**: 在测试中需要手动加载GameManager，或使用GUT的`autofree`功能。

### Q3: 场景切换时游戏状态会丢失怎么办？
**A**: 在切换前使用SaveManager保存当前状态，切换后重新加载。

### Q4: EventBus信号过多导致混乱怎么办？
**A**: 将信号按功能分组，使用清晰的命名规范。
